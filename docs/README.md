# OctoAcme Project Management Docs

## Project Management Processes

OctoAcme uses a customer-first, iterative delivery approach with clear ownership and data-informed decisions. Projects move through initiation, planning, execution, release, and close/retrospective. Initiation validates the problem, success metrics, stakeholders, and go/no-go decision. Planning turns approved work into a prioritized backlog with estimates, acceptance criteria, dependencies, milestones, a release plan, and a Definition of Done.

During execution, teams use a project board and small pull requests to deliver testable increments. The Project Manager coordinates delivery, schedules, risks, dependencies, and status reporting; the Product Manager defines outcomes and prioritizes the backlog; Developers implement and test features; QA validates quality and acceptance criteria; and stakeholders provide input and approvals. Regular standups, weekly delivery and PM–PdM syncs, milestone demos, and stakeholder updates keep work visible. Risks and dependencies are maintained in a register and escalated through team, PM, Product Lead, and Sponsor levels when needed.

Quality checks are integrated throughout delivery, including unit and integration tests, end-to-end smoke tests for critical flows, linting, security scanning, and manual QA when appropriate. Release plans include acceptance-criteria validation, passing CI and security checks, staging verification, rollback planning, stakeholder notification, and post-deployment checks. Retrospectives after sprints, releases, incidents, and other milestones convert learnings into owned, dated action items, and those improvements are reviewed and measured over time.
